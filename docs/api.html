Conventions

AspectRule
Base URLhttp://127.0.0.1:8787 by default (CAIRN_PORT / --port change the port). The server binds 127.0.0.1 only.
EncodingRequests and responses are UTF-8 JSON unless a route says otherwise (HTML pages, static files, SSE streams).
Request bodiesPOST and DELETE (and PUT/PATCH, which no route uses) must send Content-Type: application/json. Bodies are limited to 1 MB and must be a JSON object; an empty body is treated as {}.
Query stringsGET routes take parameters from the query string (URL-encoded). Integer parameters are parsed with parseInt and clamped to a safe range; invalid values fall back to the default.
PathsA trailing slash on an /api/ path is ignored (/api/stats/ = /api/stats). HEAD is accepted wherever GET is.
ErrorsAlways {"error": "message"} with a 4xx/5xx status. Unknown paths return 404; a known path with the wrong method returns 405 with an Allow header. An unexpected failure (a filesystem or system error, not a validation error) returns 500 with a generic body, {"error": "Internal server error", "id": "3f9a0c1e5b27"}; the details (which may contain internal paths) are written only to the server log as [cairn] request failed (3f9a0c1e5b27): …, so quote the id when reporting a problem.
CachingJSON responses carry Cache-Control: no-store; static files and HTML pages no-cache; the IP-range and key-directory documents public, max-age=3600.
Rolesrole is one of search (CairnSearch), corpus (CairnCorpus), user (Cairn-User). Unknown roles return 400.
CORSNone. The API is for the bundled web UI, the CLI and the research agent's MCP bridge, all same-origin or non-browser.

Security requirements for callers

The API controls a crawler, so it is guarded against the two ways a hostile web page could drive a localhost service: DNS rebinding and cross-site request forgery. Non-browser clients (curl, the CLI, the MCP bridge) pass these checks without effort; browsers pass them only from the Cairn UI itself.

Checks run in the order below; the first failure short-circuits the request with an error JSON.

#CheckApplies toRequirementFailure
1Host headerevery requestHost must be one of 127.0.0.1:<port>, localhost:<port>, [::1]:<port>, the bind address with the port, or — only when CAIRN_PUBLIC_URL is set explicitly — that URL's host (DNS-rebinding guard).421 Misdirected Request
2Bot-UA loop guardevery /api/* request, any methodThe User-Agent must not carry one of Cairn's own bot tokens followed by a version, i.e. must not match \b(CairnSearch|CairnCorpus|Cairn-User)/\d. This stops a prompt-injected research agent (fetch_page on http://127.0.0.1:<port>/api/…) or a crawl of the server from driving its own API.403 {"error": "Cairn's own bots may not call its API"}
3Origin / Sec-Fetch-Site (reads)GET, HEAD under /api/If Origin is present it must be an allowed origin (below). Sec-Fetch-Site must not be cross-site or same-site (another localhost port is same-site).403 {"error": "Cross-origin request rejected"}
4Same-origin proofGET /api/ask/stream only (it spends Claude budget and, in deep mode, starts fetches)At least one of: Sec-Fetch-Site: same-origin or none; an X-Cairn-Client header (any value — a cross-site page cannot add custom headers without a preflight); the UI's cairn_ui cookie (HttpOnly; SameSite=Strict, set on every page the server serves). Browsers without Fetch Metadata send nothing on an <img> or no-cors GET, so absence of headers is not enough here.403 {"error": "Same-origin proof required: use the Cairn UI or send an X-Cairn-Client header"}
5Origin (writes)POST, DELETE, PUT, PATCHIf an Origin header is present it must be an allowed origin: http://<Host>, http:// + any allowed host from check 1, or the explicit CAIRN_PUBLIC_URL's own origin (e.g. https://… behind a TLS proxy). An absent Origin is allowed (curl, CLI, MCP bridge).403 {"error": "Cross-origin request rejected"}
6Sec-Fetch-Site (writes)POST, DELETE, PUT, PATCHMust not be cross-site (browsers set this header themselves).403 {"error": "Cross-site request rejected"}
7Content-TypePOST, DELETE, PUT, PATCHMedia type application/json (parameters such as ; charset=utf-8 are allowed). A browser can only send this cross-origin after a CORS preflight, which Cairn never approves.415 Unsupported Media Type
8Body sizerequests with a bodyAt most 1 MB (by Content-Length or by counting the stream). The body is drained so the client can read the 413; a client that keeps sending past 16 MB is disconnected.413 Payload Too Large (with Connection: close)
9Body syntaxrequests with a bodyValid JSON whose top level is an object (not an array or scalar).400 Bad Request

Server-side limits

After routing, a few routes enforce capacity limits so one caller (or a runaway agent) cannot exhaust the machine. All limits are per server process.

LimitValueApplies toWhen exceeded
Concurrent answers4 (MAX_CONCURRENT_ASKS)POST /api/ask and GET /api/ask/stream together (each answer spawns a Claude CLI process)429 {"error": "Too many answers in progress (max 4); try again shortly"}. On the stream route this is plain JSON, sent before the stream opens. The slot is released when the answer ends or the client disconnects.
Open SSE streams64 (MAX_SSE_CLIENTS)/api/ask/stream, /api/crawl/:id/events, /api/audit/stream togetherThe 65th stream gets 503 {"error": "Too many open event streams; try again later"} with Retry-After: 5. A refused ask stream releases its answer slot without running.
Slow SSE consumer1 MiB buffered (MAX_BUFFERED_BYTES)every engine SSE streamA client that stops reading is dropped (the socket is destroyed) once more than 1 MiB of events is queued for it. It may reconnect; audit entries carry SSE ids, so a client can fill the gap with GET /api/audit?sinceId=<last id> (the engine stream itself does not replay).
Request body1 MBall requests with a body413 (see check 8)
Question length4000 characters/api/ask, /api/ask/stream400

Headers on every response: X-Content-Type-Options: nosniff, Referrer-Policy: no-referrer, X-Frame-Options: DENY, Cross-Origin-Resource-Policy: same-origin. HTML responses also carry

Content-Security-Policy: default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:;
  object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
  [; script-src 'self' 'sha256-…']   (only when the page has inline scripts, e.g. the docs' Mermaid bootstrap)

Inline scripts are allowed by exact SHA-256 hash, never by 'unsafe-inline'. No Access-Control-Allow-* headers are ever sent.

Do not expose the port. There is no authentication: anyone who can reach the socket can start crawls. Keep the default 127.0.0.1 binding; put an authenticating reverse proxy in front if you must share it.

Identity

Liveness plus Claude CLI availability (probed with <claudeBin> --version, cached 60 s). The UI header polls this.

Params: none. Errors: none (Claude being unavailable is reported in claude with an error string, not as an HTTP error). version comes from package.json.

  "name": "Cairn",
  "version": "1.0.0",

POST /api/ask

Answers a question with citations and blocks until done. quick mode retrieves passages from the index and asks Claude (no tools) to answer only from them; if Claude is unavailable it falls back to an extractive answer. deep mode runs the Claude research agent, which uses Cairn's own robots-respecting fetcher through the MCP bridge.

modelstringconfig.agent.modelClaude model alias or id, e.g. haiku, sonnet.

Degraded answers are still 200: when the index has nothing relevant the answer says so and suggests a crawl ("usedClaude": false, "note": "no-relevant-passages", no citations); when Claude is unavailable or fails, an extractive answer built from the top passages is returned with "usedClaude": false and the failure in note.

Deep mode returns "mode": "deep" and a steps array — [{type: "tool"|"tool_result", name, input, summary, isError?, ts}] — describing each tool call the agent made; citations lists only the sources the answer actually cites. If the Claude CLI is unavailable, deep mode falls back to a quick answer: "mode": "deep", "steps": [] and the reason in note.

Errors: 400 missing or over-long question, or a mode other than quick/deep; 429 when 4 answers are already running (shared with /api/ask/stream, see limits); 500 unexpected failure (generic message plus an error id).

GET /api/ask/stream?question=&mode=&model=

Same as POST /api/ask but streamed as Server-Sent Events so the UI can show progress, retrieval, tool calls and partial text. It is a GET because EventSource can only issue GETs, so the write guards (Content-Type, JSON body) do not apply to it. Because it spends Claude budget it needs same-origin proof instead (check 4): the Cairn UI passes automatically (Fetch Metadata or its cairn_ui cookie), non-browser clients must send an X-Cairn-Client header (the CLI sends X-Cairn-Client: cli), and a bare curl without it gets 403. In deep mode the agent may fetch pages as Cairn-User and start small CairnSearch crawls (≤ 25 pages, depth ≤ 2) through its MCP tools. Query parameters: question (or q), mode (quick default, or deep), model. Events: status, retrieval, tool, tool_result, text, answer, error, then done. Closing the connection aborts the run (including the Claude process). See the SSE catalogue.

Errors (as JSON, before the stream opens): 400 missing question or bad mode; 403 no same-origin proof, foreign Origin, Sec-Fetch-Site: cross-site/same-site, or a Cairn bot User-Agent; 429 4 answers already running; 503 (Retry-After: 5) 64 SSE streams already open. Failures after the stream opens arrive as an error event followed by done. A client that stops reading is dropped once 1 MiB is buffered for it, which also aborts the run.

Crawl

POST /api/crawl

Starts a crawl job immediately and returns 201. The job fetches robots.txt first for every seed origin, seeds sitemaps, then walks links breadth-first. Politeness (crawl-delay, per-host concurrency, backoff) is enforced by the fetcher, not the job.

FieldTypeDefaultDescription
seeds or urlstring[] | string—Start URL(s), required. seeds may be an array or one string separated by spaces, commas or newlines; url is a single URL. Duplicates are dropped; at most 50 seeds.
role"search" | "corpus""search"search adds pages to the index; corpus writes data/corpus/<jobId>.jsonl and does not touch the index.
maxPagesinteger 1–10000config.crawl.maxPages (50)Stop after this many fetched pages.
maxDepthinteger 0–20config.crawl.maxDepth (2)Link depth from seeds (sitemap URLs count as depth 1, so sitemaps are only read when maxDepth ≥ 1).
sameSiteOnlybooleantrueOnly follow links on the seeds' sites.
useSitemapsbooleantrueRead Sitemap: lines and /sitemap.xml.
concurrencyinteger 1–32config.crawl.concurrency (4)Parallel fetches within the job (per-host limits still apply).
includePatternsstring[] | string—Regexes (array, or one per line); if present a URL must match one.
excludePatternsstring[] | string—Regexes (array, or one per line); matching URLs are skipped.

Out-of-range integers are clamped. Booleans also accept the strings "false", "0", "no" and "off".

GET /api/crawl

All jobs (newest first; the newest 50 are kept, running jobs are never evicted) as {"jobs": [status, ...]}.

GET /api/crawl/:id

One job's status object (same shape as job above). state is one of queued, running, done, cancelled, error. recent holds the last 50 page outcomes:

"recent": [
  { "url": "http://127.0.0.1:8788/private/secret.html", "outcome": "blocked-robots", "status": null, "title": null, "depth": 1, "ts": "..." },
  { "url": "http://127.0.0.1:8788/noindex.html", "outcome": "noindex", "status": 200, "title": "Noindex test", "depth": 1, "ts": "..." },
  { "url": "http://127.0.0.1:8788/about.html", "outcome": "indexed", "status": 200, "title": "About Northwind Trails", "depth": 1, "ts": "..." }
]

Page outcomes: indexed, collected, blocked-robots, noindex, duplicate, skipped-type, http-<status>, error. Errors: 404 unknown id.

POST /api/crawl/:id/cancel

Stops a job: nothing new is scheduled and in-flight requests are aborted. Returns {"job": status}; state becomes cancelled once the job has wound down (cancelling a finished job is a no-op). Send {} or no body, with Content-Type: application/json. Errors: 404 unknown id.

GET /api/crawl/:id/events

SSE stream. It opens with one state event carrying the current status, then sends page events (one per URL outcome), a state event on each state change, and finally done with the final status, after which the server closes the stream. If the job has already finished, the opening state is followed immediately by done. Errors: 404 unknown id; 503 with Retry-After: 5 when 64 SSE streams are already open (both JSON, before the stream opens).

Fetch & Robots

POST /api/fetch

Fetches a single URL through the full compliant pipeline (robots check on every redirect hop, rate limiting, honest UA, Web Bot Auth signature, audit). Used by the Fetch inspector and the research agent's fetch_page tool.

FieldTypeDefaultDescription
urlstring—Required, http(s).
role"search" | "corpus" | "user""user"Identity to fetch as. user respects robots.txt unless robots.respectForUserFetch is turned off.
indexbooleanfalseIf true, and the fetch succeeded with HTML or text, try to add the page (under its final URL) to the search index. The index belongs to CairnSearch, so the page goes in only if CairnSearch's robots.txt rules allow it as well as the fetching role's, it is not noindex, and it is not a duplicate — see Indexing rules. corpus fetches never feed search.

POST /api/config

Validates a partial object, deep-merges it into the live config (changes take effect immediately), persists the editable keys to <dataDir>/config.json, and returns the new subset. Validation is strict so a bad request can never corrupt config.json:

  • top-level keys must be editable — host, port, dataDir, identity, publicBaseUrl ... are rejected;
  • nested keys must already exist (no new keys), and each value must match the current type: non-negative finite number, boolean, string (≤ 500 chars), object, or array of strings;
  • strings and string-array entries must not contain control characters (U+0000–U+001F, U+007F): a CR/LF in contact would otherwise break the From/User-Agent headers of every outgoing request;
  • robots.cacheTtlMs may be at most 86400000 (24 h, RFC 9309 §2.4);
  • only own keys count: __proto__, constructor and prototype are rejected as unknown keys, and the merge into the live config (and the load of config.json at startup) skips them, so a crafted patch or file cannot pollute Object.prototype;
  • agent.claudeBin can never be changed over HTTP (it names an executable) — use CAIRN_CLAUDE_BIN.

{ "politeness": { "minDelayMs": 2000, "...": "..." }, "agent": { "model": "haiku", "...": "..." }, "...": "..." }

Assistant

Everything under /api/assistant/ belongs to the desktop assistant (src/assistant/routes.js). The chat panel, the bubble app, the CLI assistant commands and the assistant MCP tool server all use these routes. They share the conventions above: JSON bodies with Content-Type: application/json on every POST and DELETE (415 otherwise), a matching Origin when one is sent (403), no cross-site Sec-Fetch-Site (403), a loopback or public-URL Host (421), bodies of at most 1 MB (413), {"error": …} on failure, and 405 with an Allow header for a known path with the wrong method. For how these pieces fit together, see Desktop assistant.

Seven groups. Two routes stream Server-Sent Events. POST /approvals and GET /approvals/:id/wait exist for the approval_prompt MCP tool, and the chat panel uses the rest.

POST /api/assistant/chat

Starts a background run and returns at once. The run keeps going if the client disconnects. A new conversation is created when conversationId is omitted, and its title is the first 60 characters of the message. When maxConcurrentRuns runs are already active (3 by default), the run starts in state queued.

Body: {message (required, ≤ 20 000 chars), conversationId?}. Errors: 400 missing message, 404 unknown conversation.

// 202 Accepted
{ "runId": "run-mfq9x2k1-3f9a0c1e", "conversationId": "c-mfq9x2k1-8b2d44a0", "background": true }

GET /api/assistant/runs?limit= · GET /api/assistant/runs/:runId

The list returns {runs}, newest first (limit 1–50, default 30). Each row is {runId, conversationId, title, state, startedAt, finishedAt, lastEvent, costUsd}. state is one of queued, running, waiting_approval, done, error or cancelled. The single-run route adds the buffered events array. The run object is also repeated under run. Errors: 404 unknown run.

GET /api/assistant/runs/:runId/events

SSE stream for one run. It first replays every buffered event and then streams live ones. Event names are the event type, each carries an id: sequence number, and a reconnecting client that sends Last-Event-ID (or ?lastEventId=) skips what it already has. The server closes the stream after done. See assistant SSE events.

POST /api/assistant/runs/:runId/cancel

Kills the run's claude -p process, or removes the run from the queue, and denies its pending approvals with "Run cancelled by the user". Returns {ok}. Errors: 404 unknown run.

GET /api/assistant/conversations · GET|DELETE /api/assistant/conversations/:id

The list returns {conversations: [{id, title, updatedAt, messageCount}]}, newest first. GET /:id returns the full conversation {id, title, createdAt, updatedAt, sessionId, allowAlways, messages}, also repeated under conversation. DELETE /:id removes the file and returns {ok:true}. Errors: 404.

GET /api/assistant/approvals?runId=

Returns {pending: [{id, toolName, input, conversationId, runId, createdAt, summary}]}, optionally only for one run. summary is a one-line description such as Run shell command: ls -la ~/Downloads.

POST /api/assistant/approvals

Called by the approval_prompt permission tool, not by people. Body: {toolName (or tool_name), input?, conversationId?, runId?} → {id}. The run moves to waiting_approval, the global stream sends approval, and after a 250 ms grace period (so "Always allow" decisions stay silent) a "Cairn needs your approval" notification appears. Undecided approvals are denied after 5 minutes.

GET /api/assistant/approvals/:id · GET /api/assistant/approvals/:id/wait?timeout=

GET /:id returns {approval}. /wait is a long-poll of up to timeout seconds (0–60, default 60). It returns {decided:true, decision:{allow, message?, always?, updatedInput?}} as soon as someone decides, or {decided:false} when the time runs out. Errors: 404 unknown approval.

POST /api/assistant/approvals/:id

Approve or deny. Body: {allow: boolean, message?, always?: boolean, updatedInput?: object}. With allow and always, the tool name is added to the conversation's allowAlways list, so later calls in that conversation run without asking. Returns {ok:true}, plus alwaysAllowed: toolName when that happened. Errors: 404 unknown, 409 already decided.

curl -s -X POST http://127.0.0.1:8787/api/assistant/approvals/ap-mfq9x7d2-51c0e9aa \
  -H 'Content-Type: application/json' -d '{"allow":true}'

GET /api/assistant/tasks?includeDone= · POST /api/assistant/tasks

GET returns {tasks} sorted by nextRunAt. Finished and cancelled tasks are included only with includeDone=1 (or all=1). A task is {id, title, kind, prompt, notes, recurrence, status, createdAt, nextRunAt, lastRunAt, runs}.

POST creates a reminder or an agent task and returns 201 {task}. Body: either {title, when} with an ISO 8601 time, or {text} in plain English, which is parsed with parseWhen ("in 10 minutes", "tomorrow at 9am", "every weekday at 8:30"). Optional: kind (reminder by default, or agent), prompt (what an agent task should do, defaults to the title), notes, and recurrence {every: minute|hour|day|week|weekday, interval?, at?: "HH:MM", days?: ["mon", …]}. With only a recurrence, the first occurrence is computed for you. Errors: 400 when no time can be worked out.

curl -s -X POST http://127.0.0.1:8787/api/assistant/tasks \
  -H 'Content-Type: application/json' \
  -d '{"text":"every weekday at 8:30 summarise my unread newsletters","kind":"agent"}'

POST /api/assistant/tasks/parse

Dry run of the natural-language parser. Body: {text}. Returns {ok:true, when, recurrence, title, parsed}, or {ok:false, parsed:null, error} (still 200) when no time is found.

GET|POST|DELETE /api/assistant/tasks/:id · POST /api/assistant/tasks/:id/run

GET returns {task}. POST is a partial update of title, notes, prompt, when and recurrence, and returns {task}. DELETE cancels the task and returns {ok, task}. /run fires it now, as if it were due, and returns {ok, task}. Errors: 404 unknown task, 400 invalid patch.

SSE event catalogue

Streams use Content-Type: text/event-stream; charset=utf-8 and Cache-Control: no-cache, no-transform. Each stream starts with retry: 3000; every message is an event: name plus one JSON data: line (audit entries also carry an id:); a : heartbeat <ISO time> comment is sent every 15 s. Clients should close the stream on done — the server closes its side, and a browser EventSource would otherwise reconnect and start over. At most 64 engine streams may be open at once (the next gets 503 JSON with Retry-After: 5), and a client with more than 1 MiB of unread events is disconnected.

curl cookbook

# Health and identity
curl -s http://127.0.0.1:8787/api/health
curl -s http://127.0.0.1:8787/api/identity

# Start a crawl, then follow it
curl -s -X POST http://127.0.0.1:8787/api/crawl \
  -H 'Content-Type: application/json' \
  -d '{"url":"http://127.0.0.1:8788/","maxPages":40}'
curl -sN http://127.0.0.1:8787/api/crawl/job-1-mfq3k2a1/events

# Search, then ask
curl -s 'http://127.0.0.1:8787/api/search?q=return+window'
curl -s -X POST http://127.0.0.1:8787/api/ask \
  -H 'Content-Type: application/json' \
  -d '{"question":"What is the return window?","mode":"quick"}'
# The streaming variant needs same-origin proof: any X-Cairn-Client value
curl -sN -H 'X-Cairn-Client: curl' 'http://127.0.0.1:8787/api/ask/stream?q=return+window&mode=quick'

# Would robots.txt let each role in?
curl -s -X POST http://127.0.0.1:8787/api/robots/check \
  -H 'Content-Type: application/json' \
  -d '{"url":"http://127.0.0.1:8788/private/secret.html"}'

# Assistant: start a background run and follow it
curl -s -X POST http://127.0.0.1:8787/api/assistant/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"Find three quiet vacuums under $250 and compare them"}'

curl -s http://127.0.0.1:8787/api/assistant/health
