CLI reference

bin/cairn.js is a single zero-dependency Node script that drives every part of Cairn from a terminal: the server, the desktop assistant (chat, remind, tasks, approvals, shopping, assistant, desktop), and the search engine's crawler, search, answers, robots diagnostics and demo.

Everything below runs against the bundled Northwind Trails fixture site on your own machine — no external network, no npm install.

Each step builds on the previous one; demo runs steps 2 to 6 automatically in one process, against a throwaway data directory.

# 0. Requirements: Node 20+. Claude CLI optional (answers fall back to extractive).
$ node --version
v20.20.0

# 1. Is everything in place?
$ node bin/cairn.js doctor

# 2. Terminal A: start the fictional outdoor-gear site on port 8788
$ node bin/cairn.js fixture --port 8788

# 3. Terminal B: how does robots.txt treat each Cairn role?
$ node bin/cairn.js robots http://127.0.0.1:8788/private/public-note.html

# 4. Crawl it as the search indexer (watch private pages get refused)
$ node bin/cairn.js crawl http://127.0.0.1:8788/ --max-pages 60 --max-depth 5

# 5. Search the local index
$ node bin/cairn.js search "ridgeback weight"

# 6. Ask with citations (quick RAG; add --deep for the research agent)
$ node bin/cairn.js ask "How much does the Ridgeback 45 weigh and what is the return window?"

# 7. See exactly what Cairn requested, as whom, and what robots.txt said
$ node bin/cairn.js audit --limit 15

# 8. Open the web UI (Ask, Crawl, Index, Fetch inspector, Robots tester, Audit, Identity, Settings)
$ node bin/cairn.js serve --open

# Or do steps 2 to 6 in one go (add --no-claude to force the offline extractive answer):
$ node bin/cairn.js demo

Synopsis & global options

node bin/cairn.js <command> [arguments] [options]
npx cairn <command> ...          # via the "bin" entry in package.json
npm start                        # = cairn serve
npm run fixture                  # = cairn fixture
npm run demo                     # = cairn demo
OptionApplies toDescription
--data-dir <dir>allUse this data directory (index, audit log, keys, corpus, config) instead of $CAIRN_HOME / ./data. Relative paths are resolved against the current directory.
--json, -jcrawl, search, ask, fetch, robots, keys, stats, audit, index list, doctor, chat, remind, tasks, approvals, shoppingPrint one machine-readable JSON document on stdout. Progress lines (crawl pages, ask steps) go to stderr, so | jq just works.
--port <n>, -pserve, fixture, and the assistant commandsFor serve and fixture, the port to listen on. For assistant commands, the port of the running server to talk to (default: the configured port).
--no-colorallDisable ANSI colours. Colours are also off when stdout is not a TTY or NO_COLOR is set; FORCE_COLOR=1 forces them on.
--help, -hallPrint the help text (same as help).
--version, -vallPrint cairn 1.0.0 (from package.json).

Parsing rules: options may appear before or after positional arguments; --name value and --name=value are equivalent; boolean flags accept --flag=false / =0 / =no; a value may not start with --; everything after a bare -- is positional. Short aliases: -n = --limit, -p = --port, -j = --json. Repeating a value option keeps the last value, except --include/--exclude, which accumulate. Unknown options are a usage error (exit 2).

Only serve, fixture, demo and ask --deep open a listening socket. The assistant commands are HTTP clients of a running server, because the assistant's runs, approvals and scheduler live in the server process. Every other command runs in-process directly against the data directory, so it works without a running server. Avoid running a crawl from the CLI while serve is writing the same data directory.

The CLI reuses the server's own helpers (crawlOptions, fetchAndExtract, robotsDecisions, ask), so a command and its HTTP API twin validate input and produce results identically — and neither can bypass robots.txt or politeness.

serve

Starts the HTTP API and web UI. Runs until Ctrl-C / SIGTERM, then closes open streams, saves the index and closes the audit log.

cairn serve [--port <n>] [--host <addr>] [--open]
OptionDefaultDescription
--port <n>, -p$CAIRN_PORT or 8787Listen port, 0–65535. 0 picks a free port.
--host <addr>$CAIRN_HOST or 127.0.0.1Bind address. Keep the loopback default: the API has no authentication.
--openoffOpen the dashboard in the default browser (open / xdg-open / explorer).
$ node bin/cairn.js serve

crawl

Runs a crawl job in-process and prints each page outcome live, then a summary. robots.txt is fetched first for every origin; Crawl-delay, per-host spacing (politeness.minDelayMs) and backoff are enforced by the fetcher. Ctrl-C cancels the job gracefully; a second Ctrl-C quits immediately (exit 130).

cairn crawl <url...> [--role search|corpus] [--max-pages <n>] [--max-depth <n>] [--concurrency <n>]
                     [--no-sitemaps] [--any-site] [--include <regex>]... [--exclude <regex>]... [--json]
OptionDefaultDescription
<url...>—One or more absolute http(s) seed URLs (required; at most 50).
--role search|corpussearchsearch (UA token CairnSearch) adds pages to the index. corpus (CairnCorpus) appends to <dataDir>/corpus/<jobId>.jsonl and leaves the index alone.
--max-pages <n>crawl.maxPages (50)Stop after n fetched pages (integer ≥ 1).
--max-depth <n>crawl.maxDepth (2)Maximum link depth from the seeds (integer ≥ 0). Sitemap URLs count as depth 1.
--concurrency <n>crawl.concurrency (4)Parallel fetches within the job, 1–32 (per-host limits still apply).
--no-sitemapssitemaps onDo not read Sitemap: lines or /sitemap.xml.
--any-sitesame-site onlyFollow links to other sites (their robots.txt is still fetched and honoured).
--include <regex>—Only URLs matching one of these patterns are enqueued. Repeatable.
--exclude <regex>—URLs matching any of these patterns are skipped. Repeatable.
--jsonoffProgress to stderr; the final job status object (as in GET /api/crawl/:id) to stdout.

Each progress line shows elapsed time, outcome, HTTP status (--- when nothing was fetched), depth, URL and title.

ask

Answers a question with numbered citations. Quick mode (default) retrieves passages from the index and asks Claude (no tools) to answer only from them; without a working Claude CLI it prints an extractive answer instead. Deep mode (--deep) runs the Claude research agent: the CLI starts an in-process API server on an ephemeral loopback port so the agent's MCP bridge can search the index, fetch pages as Cairn-User (robots-respecting), crawl small scopes and check robots.txt. If Claude is unavailable, deep mode falls back to a quick answer.

cairn ask <question...> [--deep] [--model <alias>] [--json]
OptionDefaultDescription
<question...>—The question (quote it); at most 4000 characters.
--deepquickUse the research agent.
--model <alias>agent.model ($CAIRN_MODEL or sonnet)Claude model alias or id, e.g. haiku.
--jsonoffThe full result object, same as POST /api/ask.

Progress (status lines, retrieval, and in deep mode each tool call → and result ←) is written to stderr; the answer to stdout.

Assistant commands

The assistant commands are thin HTTP clients of the running server. They do not build the runtime in-process like the engine commands do. They call /api/assistant/* on http://127.0.0.1:<port>, where the port is --port if given, otherwise the configured port ($CAIRN_PORT or 8787, read through --data-dir / $CAIRN_HOME). Start the server first with serve, or with desktop, whose app starts it for you. If nothing answers, the command prints the error below and exits 1:

Cairn is not running at http://127.0.0.1:8787 (ECONNREFUSED).
Start it with 'node bin/cairn.js serve' or 'node bin/cairn.js desktop'.

A server that answers but has no assistant routes (an older build) gives The server at … has no assistant API (an older Cairn?). Restart it. Every assistant command accepts --json, which prints the API response on stdout. Chat progress lines go to stderr, so | jq works.

CommandOptionsAPI calls
chat <message>--conversation ID, --no-follow, --json, --port NPOST /api/assistant/chat, then GET /api/assistant/runs/:runId/events (SSE)
remind <text>--json, --port NPOST /api/assistant/tasks {text}
tasks [list | cancel <id> | run <id>]--all (list), --json, --port NGET /api/assistant/tasks, DELETE /api/assistant/tasks/:id, POST /api/assistant/tasks/:id/run
approvals [list | approve <id> | deny <id>]--always (approve), --message M (deny), --json, --port NGET /api/assistant/approvals, POST /api/assistant/approvals/:id

chat

Sends a message to the assistant. This starts a background run, and the command then follows it live. Assistant text goes to stdout. Status lines (·), tool calls (→), tool results (←) and approval requests go to stderr. When a tool needs approval, the command prints the exact approvals approve / deny commands, and you can also decide in the chat panel or the bubble. Ctrl-C detaches: the run keeps going on the server, and you get a macOS notification when it finishes.

cairn chat <message…> [--conversation <id>] [--no-follow] [--json]

--no-followoffStart the run and return at once: Started run … in the background. Follow it in the assistant: http://127.0.0.1:8787/assistant.
--jsonoffAt the end, print {runId, conversationId, background, state, text, costUsd} on stdout. Streamed text goes to stderr instead.

remind

Schedules a reminder from plain English, without involving Claude. The text is parsed on the server by parseWhen, which understands forms such as "in 10 minutes", "at 5pm", "tomorrow at 9am", "tonight", "next monday at 10", "every weekday at 8:30" and "every 30 minutes". Phrases like "remind me to" are removed from the title. When the fire time comes, you get a macOS notification and the avatar switches to its attention state.

cairn remind <text…> [--json]
$ node bin/cairn.js remind "tomorrow at 9am call mom"
✔ Scheduled call mom for Thu, Oct 1, 9:00 AM (once, id task_mfqa3x0e0c1d2e3f)

$ node bin/cairn.js remind "every weekday at 8:30 standup"
✔ Scheduled standup for Thu, Oct 1, 8:30 AM (every weekday at 08:30, id task_mfqa3y9k4a5b6c7d)

If no time can be found, the server answers 400 and the command exits 1 with Could not work out when from "…" — try e.g. "in 10 minutes", "tomorrow at 9am" or "every weekday at 8:30". Recurring agent tasks (a prompt Claude runs on a schedule) are created by asking in chat, for example "every weekday at 8:30 summarise the tech news", or with POST /api/assistant/tasks and kind: "agent".

tasks

Lists and manages reminders and recurring tasks. The subcommand defaults to list.

cairn tasks [list] [--all] [--json]    # upcoming tasks, soonest first; --all adds done and cancelled ones
cairn tasks cancel <id>                 # stop a task (recurring tasks stop repeating)
cairn tasks run <id>                    # fire it now, as if it were due (waits up to 10 min for agent tasks)
$ node bin/cairn.js tasks
  standup  [reminder]
    id task_mfqa3y9k4a5b6c7d  next Thu, Oct 1, 8:30 AM  repeat every weekday at 08:30  active
  Summarise the tech news  [agent]
    id task_mfqa40aa9e8f7a6b  next Thu, Oct 1, 8:30 AM  repeat every weekday at 08:30  active

An empty list prints a hint to use remind. An unknown id exits 1 with Unknown task: …. A subcommand other than list, cancel or run, or a missing id, is a usage error (exit 2).

desktop

Launches the floating avatar bubble: the installed /Applications/Cairn.app (or ~/Applications/Cairn.app) if there is one, otherwise desktop/build/Cairn.app, built first if needed. --install installs it into Applications and keeps it in the Dock, so you can start it from the Dock, Spotlight, the Apps view (Launchpad) or Finder. This is macOS only. On other platforms it exits 1 and suggests assistant. The command runs bash desktop/install.sh (with --install) or bash desktop/run.sh with the flags below and exits with that script's status. The app starts the server itself if nothing is answering on the port. See Floating bubble app.

Precedence: command-line option > <dataDir>/config.json > environment variable > built-in default. config.json only holds the editable keys (contact, agent, politeness, robots, crawl, fetch, signing) and is written when settings are saved from the UI or POST /api/config. Port, host, public URL and data directory are never persisted, so their variables always apply.
