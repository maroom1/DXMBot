Security model

Cairn is a single-user local tool. This page covers what it protects: the operator's machine and browser, the sites it visits, and the operator's Claude budget. It explains how each protection works, and it states plainly what is out of scope.

Localhost binding

The server binds 127.0.0.1 by default (config.host, CAIRN_HOST). Nothing listens on external interfaces, and the demo fixture site also binds loopback. The API has no authentication. The loopback binding plus the Host and Origin guards below are the entire access-control story, so do not bind 0.0.0.0 or put Cairn behind a reverse proxy without adding authentication first.

DNS-rebinding Host guard

In a DNS-rebinding attack, a malicious page at evil.example re-resolves its own name to 127.0.0.1. The browser's same-origin policy then treats calls to the local API as same-origin. The browser still sends Host: evil.example:8787, so Cairn rejects every request whose Host is not exactly 127.0.0.1:<port>, localhost:<port>, [::1]:<port>, the bind address with the port, or the host of an explicitly configured CAIRN_PUBLIC_URL, with 421 Misdirected Request.

Guards run before routing (createRequestHandler in src/server/app.js), so no handler ever sees a request with a foreign Host, a cross-site Origin or one of Cairn's own bot User-Agents.

CSRF guard

  • JSON only for state changes. Every POST and DELETE must send Content-Type: application/json. HTML forms cannot send that type, and a cross-origin fetch with it triggers a CORS preflight. Cairn answers preflights with no Access-Control-Allow-* headers, so the browser never sends the real request.
  • Origin check. If an Origin header is present, it must equal the server's own origin, or the request gets 403. Requests without an Origin (CLI, curl, the MCP server) are allowed. Modern browsers always send Origin on cross-site POSTs, and a request with a JSON body cannot be forged by a plain HTML form.
  • Side-effecting GETs. A foreign page can trigger a GET without CORS (<img>, EventSource), and GET /api/ask/stream spends Claude budget and, in deep mode, starts fetches. So every API GET is refused (403) when Origin is foreign or Sec-Fetch-Site is cross-site or same-site (another localhost port), and /api/ask/stream additionally needs positive proof, because a browser without Fetch Metadata sends no header at all: Sec-Fetch-Site: same-origin/none, an X-Cairn-Client header (a cross-site page cannot add one without a preflight), or the UI's cairn_ui cookie (random per server start, HttpOnly; SameSite=Strict).
  • Allowed origins. http:// plus any allowed Host, and the explicit CAIRN_PUBLIC_URL origin (so an https:// TLS proxy in front works).
  • No CORS headers. Cairn never emits Access-Control-Allow-Origin, so other origins cannot read responses, including SSE streams.

SSRF and blockPrivateNetworks

Cairn fetches URLs that come from crawl seeds, discovered links, redirects and the research agent. With config.fetch.blockPrivateNetworks: true, Fetcher.screen() refuses a target before any network activity — the first request, every redirect hop, and the robots.txt fetch (and its redirects) — when its host is in one of the ranges below (isPrivateHost in src/util/url.js). Page fetches return blocked: {reason: 'private-network'} with an audit entry; a refused robots.txt request is reported as "unreachable" (status 0), so that origin is disallow-all rather than allow-all.

FamilyBlocked
Nameslocalhost, *.localhost (a trailing dot is ignored); any other name whose DNS answers include a blocked address (all addresses are checked; 127.0.0.1.nip.io-style names are caught)
IPv40.0.0.0/8, 10/8, 127/8, 100.64/10 (CGNAT), 169.254/16, 172.16/12, 192.168/16, 192.0.0/24, 198.18/15 (benchmarking), 224/4 multicast and everything above (reserved, broadcast)
IPv6::, ::1, fc00::/7, fe80::/10, fec0::/10, ff00::/8 multicast
IPv4 embedded in IPv6IPv4-mapped ::ffff:a.b.c.d, deprecated IPv4-compatible ::a.b.c.d and NAT64 64:ff9b::/96 — blocked when the embedded IPv4 address is in a blocked range above
It is off by default, because the bundled demo site and the tests run on 127.0.0.1. Turn it on (POST /api/config {"fetch":{"blockPrivateNetworks":true}}) whenever you crawl the open web with the research agent enabled. Otherwise, prompt-injected text could ask the agent to fetch_page internal services. (Cairn's own API is protected either way: requests carrying a Cairn bot User-Agent get 403.) Limitation: the DNS check and the connection resolve the name separately, so a name that changes its answer between the two (DNS rebinding against the fetcher) is not caught, and a failed lookup is left to the request itself. Use network-level egress controls if that matters to you.

The scheme is always checked: only http: and https: URLs are fetched (normalizeUrl returns null for anything else). Credentials in URLs (user:pass@) and fragments are stripped during normalisation.

Outbound honesty: no UA spoofing

Every request carries the role's real UA (CairnSearch/1.0, CairnCorpus/1.0 or Cairn-User/1.0, plus +…/bot), a From: contact header, and Web Bot Auth signature headers when signing is enabled. There is no code path that sets a browser UA, rotates IPs, sends cookies or retries around a block. This is a security property as well as an ethical one: the operator's traffic is attributable, and nobody can mistake it for an attack tool.

robots.txt on every redirect hop

Redirects are followed manually (up to config.fetch.maxRedirects, 5 by default). Each hop is re-validated for scheme, private network and robots.txt before it is requested. A cross-origin hop loads the new origin's robots.txt first. A redirect therefore cannot be used to launder a disallowed URL.

Claude CLI isolation

The Claude CLI is the most capable component, so it gets the tightest box. src/agent/claude.js starts it with child_process.spawn using an argument array and no shell. The prompt is written to stdin, so no question text is ever interpolated into a command line.

The only path from the model to the web is the MCP server, then the HTTP API, then the same Fetcher every other component uses. A robots refusal comes back to the model as tool-result text, and the system prompt tells it to respect refusals.

MCP stdout hygiene

src/agent/mcp-server.js speaks JSON-RPC 2.0 as newline-delimited JSON over stdio. stdout carries protocol frames only, and every log line goes to stderr. This prevents a whole class of bugs and injection risks: a stray console.log that corrupts framing, or page text echoed to stdout that the client parses as a protocol message. Page content only ever travels inside a JSON-encoded tools/call result ({content:[{type:'text', text}]}), so it cannot break out of the frame. The server talks only to CAIRN_API on loopback, and it records source ids in the temporary CAIRN_SOURCES_FILE.

XSS-safe rendering

  • The web UI never assigns unescaped server data to innerHTML. Titles, snippets, headers and audit fields go in through textContent or are escaped first.
  • Markdown (answers and extracted pages) is escaped first, then a minimal formatter adds headings, bold, code, lists and links. Raw HTML in the source can never survive. Link targets must be http(s):. Index URLs are already normalised by normalizeUrl, which drops every other scheme, and the renderer must also refuse javascript: links in model output.
  • HTML responses carry Content-Security-Policy: default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:, which blocks inline and third-party scripts. All responses carry X-Content-Type-Options: nosniff.
  • No CDN assets. Mermaid for these docs is served locally from docs/assets/mermaid.min.js with securityLevel: 'strict'.

Signing-key storage

The Web Bot Auth Ed25519 key pair is generated on first run in data/keys/. ed25519-private.pem is written with mode 0600, so only the operator's account can read it. ed25519-public.pem and the JWKS at /.well-known/http-message-signatures-directory are public by design. The key id is the RFC 7638 JWK thumbprint. The private key is never served, logged or sent to Claude.

Rotation: stop Cairn, delete data/keys/ and restart. A new key id is published immediately. Site owners who pinned the old key id must update. Signatures expire 300 s after creation and carry a random nonce, which limits replay.

Audit trail

Every HTTP attempt (including robots.txt fetches and retries), every robots block, crawl events and agent runs (model, cost, duration, success) are appended to data/audit.ndjson by src/util/audit.js. The last 2000 entries are also kept in memory for the UI and GET /api/audit, and new entries stream over GET /api/audit/stream. Fetch entries record role, token, URL, final URL, status, bytes, elapsed time, robots decision and matched rule, block reason, whether the request was signed, and the attempt number. If a site owner asks what Cairn did on their site, the log answers it.

Nothing leaves the machine except outbound fetches and the prompts the Claude CLI sends to Anthropic. There is no automatic expiry. The operator owns retention.

  • Page text of public pages is stored unencrypted in index.json and in corpus JSONL files. Treat the data directory as containing third-party content, and respect the source sites' terms when you share or reuse it.
  • Questions and retrieved passages are sent to Anthropic through the Claude CLI under the operator's own account and data policy. Cairn itself does not store transcripts (the CLI runs with --no-session-persistence).
  • Temporary files (the MCP config and the sources registry for deep research) live in the OS temp directory for the duration of a run.
  • Use CAIRN_HOME or --data-dir to keep separate, disposable data directories per project.

What is NOT protected

Know these limits before you rely on Cairn.
Not protectedWhy / what to do
Other local users or processes calling the APIThe API has no authentication. Any process on the machine can call 127.0.0.1:8787. Do not run Cairn on shared multi-user hosts.
Network exposureBinding to a non-loopback interface or putting Cairn behind a proxy is unsupported. The Host guard will also reject the proxied Host.
Private-network SSRF by defaultblockPrivateNetworks is off by default. When on, it checks DNS answers but cannot stop a name that re-resolves between the check and the connection. Enable it for open-web research and add egress firewalling if needed.
Answer integrity against prompt injectionA malicious page can still bias or falsify an answer drawn from it. Citations let the reader check, but Cairn does not detect injection.
Data at restThe index, corpus and audit log are plain files. Use full-disk encryption. Only the private key has restrictive permissions.
A compromised operator accountWhoever controls the account controls the key, the data and the Claude CLI credentials, which the CLI manages outside Cairn.
Local TLSThe local API is plain HTTP on loopback. That is acceptable only because it never leaves the machine.
Trust in Node.js and the Claude CLIWith zero npm dependencies, the supply chain is Node.js itself plus the Claude CLI binary. Keep both updated from trusted sources.
Sites' content, from anyone elserobots.txt is a voluntary protocol. Cairn honours it, but that gives site owners no protection against clients that do not.
Legal or terms-of-service complianceHonouring robots.txt is necessary but not sufficient. The operator is responsible for how collected content is used, especially corpus data.
