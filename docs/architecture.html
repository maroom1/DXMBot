Architecture

Design principles

The architecture follows from a handful of decisions that every module respects. Each one keeps compliance in a single place, so no code path can get around it by accident.

One fetcher, every role

Crawls, the Fetch inspector, quick answers and the research agent all send HTTP through Fetcher. It is the only place that applies robots.txt, politeness, signing and audit.

Honest identity

Three roles (CairnSearch, CairnCorpus, Cairn-User) plus the family token Cairn. The User-Agent links to /bot. No UA spoofing, no IP rotation.

Politeness is central

HostScheduler owns per-host delay, concurrency and backoff. The crawler never sleeps on its own, so Crawl-delay and Retry-After always apply.

Agent via the API only

Claude drives research through an MCP server that can only call Cairn's HTTP API. That means it goes through the same robots checks and audit as everything else.

Everything is audited

Every HTTP attempt, robots fetch, robots block, crawl event and agent run becomes one AuditLog entry. Entries go to memory, disk and live SSE.

Local by default

Servers bind 127.0.0.1. A Host-header guard, an Origin (CSRF) guard and a JSON-only POST rule protect the API. There are zero npm dependencies.

Every component gets the same mutable config object and reads values when it uses them. The server rewrites config.publicBaseUrl after binding a port, and this is how the User-Agent and Signature-Agent pick up the real port.

Level 1 — System context

Cairn sits between people who ask questions and the websites that hold the answers. Site owners never talk to Cairn directly. They control it through robots.txt and page-level signals, and they can verify it through the public bot page and key directory.

The Fetcher gets its scheduler, signer and audit through its constructor instead of importing them. That dependency injection lets tests pass in fakes, including a fake fetchImpl. The robots cache is not a separate step. The Fetcher constructor creates it with fetchRobots = (url, role) => this.fetchRaw(url, {role, kind: 'robots'}), and the runtime exposes it as runtime.robots. Shutdown cancels jobs first, so no new pages are added while the index is being saved.

  1. Config is resolved first. Everything below holds a reference to the same object.
  2. The audit log comes before the signer and the fetcher, so the very first network action can be recorded.
  3. The signer loads or creates its key pair before any request is signed.
  4. The index is loaded from disk before the job manager starts, so duplicate detection sees existing documents.
  5. The server is optional. When it binds to port 0, the real port reaches the User-Agent and Signature-Agent through config.publicBaseUrl.

Assistant layer

The desktop assistant sits on top of the engine. It adds a native app (desktop/), a compact web UI (web/bubble.* and web/avatars/*), and the src/assistant/ modules, which run inside the same cairn serve process. src/server/api.js hands every /api/assistant/* request to handleAssistantApi() in routes.js, and the assistant is created once per runtime (assistantFor(runtime)) so the scheduler starts with the server. The engine becomes one of the assistant's skills: the cairn MCP server gives Claude its search, fetch and robots tools. The user-facing view is on Desktop assistant and Floating bubble app.

The MCP config is written to a temporary file with mode 0600 for each run. CAIRN_API, CAIRN_CONVERSATION_ID, CAIRN_RUN_ID and CAIRN_UNATTENDED reach the assistant tools through their environment, so an approval request is tied to the right run. The app never starts a second server: if something already answers on port 8787 it is adopted and never restarted.
