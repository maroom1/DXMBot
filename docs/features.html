User-triggered fetches and robots.txt

The vendors differ most on user-triggered fetches. When a person asks the assistant to open a URL, is that request governed by robots.txt?

Figure 2 — How each family treats a user-triggered fetch
flowchart LR
  Q{"A person asks the assistant
to open a URL"}
  Q --> OA["OpenAI ChatGPT-User
robots rules may not apply"]
  Q --> GO["Google-Agent
generally ignores robots.txt"]
  Q --> XA["xAI user fetch
undocumented, reportedly not honoured"]
  Q --> AN["Anthropic Claude-User
honours robots.txt"]
  Q --> CA["Cairn-User
honours robots.txt by default
config.robots.respectForUserFetch"]
  CA --> REF["Blocked: the agent gets a refusal
and an audit entry is written"]

Cairn follows Anthropic's position and makes it the default. An operator can turn it off (for example, to fetch their own site), and the choice is visible in the audit trail and on the /bot page.

"By design" rows are the two places where Cairn deliberately differs from the vendors. It does not consolidate crawls across purposes, and it applies robots.txt to user-triggered fetches by default.

Deliberately not implemented

These are refusals, not backlog items. Each one would make Cairn harder for site owners to identify or control. Adding any of them would violate the project's hard rules in SPEC.md.
PracticeWhy it is temptingWhy Cairn refusesWhat Cairn does instead
User-Agent spoofing (sending Chrome or Safari strings; this is reported of xAI traffic)Gets past UA-based blocks and bot-management rulesIt is deceptive, it defeats the site owner's robots.txt and firewall choices, and it makes the operator's traffic indistinguishable from an attackEvery request names its role token and links to /bot. Requests are signed so the identity can be verified
Residential or rotating IP poolsAvoids per-IP rate limits and IP-reputation blocksIt evades rate limits the site set on purpose and makes published IP ranges meaninglessEgress uses the operator's own address. The ranges are published in /bot/*.json (configurable in config.identity)
Ignoring robots.txt for user-triggered fetches by default (the ChatGPT-User and Google-Agent position)Answers never hit "blocked"A research agent can issue many "user" fetches. Treating them all as exempt turns the agent into an unthrottled crawlerrespectForUserFetch: true by default. Turning it off is an explicit operator choice, and it is audited
CAPTCHA solving (human farms or ML solvers)Unlocks protected pagesA CAPTCHA is an explicit "humans only" signal. Anthropic's stated policy is the sameA challenge page is just a response. Cairn records the status and moves on
Headless-browser or TLS-fingerprint mimicryDefeats JavaScript and TLS bot detectionThis is evasion by definitionPlain Node fetch with honest headers. Pages that only render client-side are out of scope
Login-wall or paywall bypassMore contentIt is outside the site owner's intended audience and may breach terms or lawCairn never sends cookies or credentials and fetches public URLs only
Retrying through 429 without backoffFaster crawlsIt harms the site and gets the operator blockedExponential backoff that honours Retry-After, and the host is penalised in HostScheduler

Sources and research notes

  • OpenAI, Overview of OpenAI crawlers: developers.openai.com/api/docs/bots. Covers OAI-SearchBot, GPTBot, OAI-AdsBot and ChatGPT-User, the four IP JSON files, the roughly 24 h robots.txt propagation for search, and that "results from a single crawl" may be used for multiple bots when a site allows both.
  • Anthropic, Does Anthropic crawl data from the web, and how can site owners block the crawler?: support.claude.com/en/articles/8896518. Covers ClaudeBot, Claude-User, Claude-SearchBot, Crawl-delay support, no CAPTCHA bypass and the published IP list.
  • Google, User-triggered fetchers: developers.google.com/crawling/…/google-user-triggered-fetchers. Covers Google-Agent (added March 2026), the note that user-triggered fetchers "generally ignore robots.txt rules", user-triggered-agents.json, and the Web Bot Auth experiment with https://agent.bot.goog. Google-Extended is documented under Google's common crawlers.
  • xAI: no official crawler documentation page was found. Third-party directories and reports (for example menra.ai and nohacks.co) describe a training crawl, DeepSearch retrieval and user-triggered fetches, and report spoofed browser UAs and residential IPs. Treat these as unverified.
  • IETF, HTTP Message Signatures for automated traffic Architecture: draft-meunier-web-bot-auth-architecture. Also RFC 9421 (HTTP Message Signatures), RFC 7638 (JWK Thumbprint) and Cloudflare's web-bot-auth reference implementation and verified-bots programme.
  • RFC 9309, Robots Exclusion Protocol. Covers matching, the 500 KiB limit and error handling. Crawl-delay and Sitemap are widely used extensions and are not part of the RFC's core rules.
  • llms.txt (proposed September 2024). Adoption studies in 2026 found that most published files receive almost no bot traffic, and no major AI vendor has committed to using third-party llms.txt files for crawling.
