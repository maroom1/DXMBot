Claude agent & MCP

How Cairn uses the Claude Code CLI as its answer engine. Quick mode is retrieval-augmented generation with no tools. Deep mode is a research agent that Claude drives through Cairn's own MCP tools, so every page it reads is fetched by Cairn's robots-respecting, rate-limited, audited fetcher.

1. Two modes

Quick: mode:'quick'

src/agent/answer.js. Cairn retrieves up to config.agent.maxPassages (8) passages from the local index and sends them to Claude as numbered sources. Claude has no tools, so it can only answer from what it is given. If Claude is unavailable, Cairn falls back to an extractive answer. Typical time is a few seconds.

Deep: mode:'deep'

src/agent/research.js. Claude gets exactly five MCP tools (search, fetch, crawl, robots check, stats) served by src/agent/mcp-server.js, which proxies to Cairn's HTTP API. Claude plans and iterates, then writes a cited answer. It needs the Claude CLI and is limited by the budget and timeout.

Shared runner

src/agent/claude.js. runClaude() spawns the CLI, writes the prompt to stdin, parses NDJSON from stdout, normalizes events for the UI and SSE, and enforces the timeout, abort signal and budget.

Quick mode always produces an answer, even without Claude. Deep mode depends on Claude, but every web access it makes still goes through the compliant fetcher.

2. Claude CLI invocation

Cairn calls the Claude Code CLI (config.agent.claudeBin, default claude, overridable with CAIRN_CLAUDE_BIN) instead of an HTTP SDK. This keeps Cairn free of npm dependencies, reuses the user's existing Claude login, and gives a well-defined, sandboxable subprocess boundary. The process is started with child_process.spawn and an argument array. No shell is involved, so nothing in a question can inject shell syntax.

claude -p --output-format stream-json --verbose --no-session-persistence \
  --model sonnet \
  --tools "" \
  --strict-mcp-config \
  --mcp-config /tmp/cairn-research-7Qx1/mcp.json \
  --allowedTools mcp__cairn__search_index,mcp__cairn__fetch_page,mcp__cairn__crawl_site,mcp__cairn__check_robots,mcp__cairn__index_stats \
  --system-prompt "<research system prompt>" \
  --max-budget-usd 1.5 \
  --permission-prompts none
# prompt text is written to stdin; cwd = <dataDir>/agent-work (an empty directory)

The working directory defaults to <dataDir>/agent-work, which is created empty, so the CLI never loads the project's CLAUDE.md or any other context file. claudeAvailable(config) runs <bin> --version and caches the result for 60 s. The health endpoint and the web UI header report it.

All flags above were checked against claude --help for Claude Code 2.1.x.

4. Quick mode (RAG)

  1. runtime.index.searchPassages(question, {limit: config.agent.maxPassages}) returns up to 8 BM25-ranked passages of about 120 words each. Pages marked nosnippet contribute their title only.
  2. If nothing is found, Cairn does not call Claude. The answer says the index has nothing relevant and suggests crawling a site first.
  3. Otherwise the passages are numbered [1]…[k] and embedded in the prompt. Claude runs with no tools and no MCP servers.
  4. The [n] markers in Claude's answer are mapped back to {n, url, title}. Only the sources actually cited are returned.
  5. If Claude is unavailable or the run fails, the answer is extractive instead: the top 3 passages, each cited, with usedClaude:false.
  6. An audit.record({kind:'agent', mode:'quick', model, costUsd, durationMs, ok}) entry is written.

Quick mode never touches the network except for the Claude API call made by the CLI. It only reads Cairn's local index.

5. Deep mode (Claude drives MCP tools)

deepResearch(question, {runtime, apiUrl, onEvent, model}) gives Claude a research loop. It needs a running Cairn HTTP API for the MCP server to call. cairn ask --deep starts an in-process server on an ephemeral port (port: 0) for this. From the web UI, the running server is used.

Temporary MCP config

{
  "mcpServers": {
    "cairn": {
      "command": "/usr/local/bin/node",
      "args": ["/Users/me/DxBot/src/agent/mcp-server.js"],
      "env": {
        "CAIRN_API": "http://127.0.0.1:8787",
        "CAIRN_SOURCES_FILE": "/var/folders/…/cairn-research-7Qx1/sources.json"
      }
    }
  }
}

command is process.execPath, the same Node binary running Cairn, so no PATH lookup is needed. The config and sources files live in a fresh fs.mkdtemp directory under the OS temp dir. That directory is removed after the run.

Claude never opens a socket to a website itself. Every page it reads is fetched by Cairn as Cairn-User, under robots.txt, rate limits, signing and the audit log.

6. MCP server protocol

src/agent/mcp-server.js is a small stdio MCP server with no dependencies. It speaks JSON-RPC 2.0 with one JSON message per line. stdout carries protocol messages only. All logging goes to stderr, because a stray console.log would corrupt the stream.

MethodKindResponse
initializerequest{protocolVersion: <client's version, or "2025-06-18">, capabilities: {tools: {}}, serverInfo: {name: "cairn", version: "1.0.0"}}
notifications/initializednotificationNone (notifications have no id and get no reply)
pingrequest{}
tools/listrequest{tools: [{name, description, inputSchema}, …]}: the five tools below
tools/callrequest{content: [{type: "text", text}], isError?}
anything elserequestJSON-RPC error -32601 "Method not found"

Failures inside a tool, such as the API being unreachable, an invalid URL or a robots refusal, are returned as a normal tools/call result with isError: true and a readable message. They are not JSON-RPC errors, so the model can read them and change course.

→ {"jsonrpc":"2.0","id":0,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"claude-code","version":"2.1"}}}
← {"jsonrpc":"2.0","id":0,"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{}},"serverInfo":{"name":"cairn","version":"1.0.0"}}}
→ {"jsonrpc":"2.0","method":"notifications/initialized"}
→ {"jsonrpc":"2.0","id":1,"method":"tools/list"}
← {"jsonrpc":"2.0","id":1,"result":{"tools":[{"name":"search_index","description":"…","inputSchema":{…}}, …]}}
→ {"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"check_robots","arguments":{"url":"http://127.0.0.1:8788/private/secret.html"}}}
← {"jsonrpc":"2.0","id":2,"result":{"content":[{"type":"text","text":"Cairn-User: DISALLOWED by \"Disallow: /private/\" (group *) …"}]}}

← {"jsonrpc":"2.0","id":3,"error":{"code":-32601,"message":"Method not found: resources/list"}}

The server has no state except the source registry, which lasts for the session. It exits when the CLI closes its stdin.

Values above the caps are clamped (for example, maxPages: 500 becomes 25). A crawl_site job that is still running after 90 s keeps running in the background. The tool returns the progress so far so the model can decide whether to wait or move on.

8. Source-id registry and citation mapping

Answers must cite URLs that Cairn really retrieved, so source numbers are assigned by the MCP server, not by the model:

  • Every URL a tool returns (search hits, fetched pages, crawled pages) is registered in a session map url → n. Numbers start at 1 and never change for the rest of the session. A URL seen again keeps its number.
  • Tool output always shows the id next to the URL, for example [3] Summit Shell — http://…/products/summit-shell.html, so the model can cite [3].
  • After every change, the registry is written to CAIRN_SOURCES_FILE as [{n, url, title}].
  • When the run ends, research.js reads the file and scans the answer for [n] markers. It keeps the ones that exist in the registry, in order of first appearance, and without duplicates. The original numbers are kept, so the answer text never needs rewriting. Numbers the model made up match nothing and are dropped.

10. Safety and cost controls

RiskControl
The model bypasses robots.txt or rate limits by fetching directly--tools "" removes WebFetch, WebSearch and Bash. The only route to the web is fetch_page / crawl_site, which go through the Fetcher as Cairn-User / CairnSearch, with robots checks, per-host pacing, signing and audit logging.
Prompt injection from fetched pagesThe system prompts mark source text as untrusted. The model has no powerful tools: no shell, no file access, no outbound HTTP of its own, and no tool that writes anywhere except Cairn's local index. The worst an injected page can do is waste budget or steer the answer, and the answer still has to cite real, registered sources.
Other MCP servers or user settings leak into the run--strict-mcp-config plus a temporary config with only cairn. The empty cwd means no CLAUDE.md is loaded.
A permission prompt blocks a headless run--permission-prompts none denies anything not on the allowlist instead of waiting.
Runaway cost--max-budget-usd (default $1.50), capped crawls (25 pages, depth 2), fetched pages truncated to 12k characters, at most 8 RAG passages. costUsd is recorded per run in the audit log.
Hung processconfig.agent.timeoutMs (240 s). The child is killed on timeout or client abort (signal).
Session and history leakage--no-session-persistence. Temporary MCP and source files are deleted after the run.
The MCP bridge is reachable by othersThe API it calls is bound to 127.0.0.1, with the Host-header (DNS-rebinding) and Origin checks described in the security model.
