Why "Cairn"

A cairn is a stack of stones that marks a trail. It guides travellers without harming the land. The name describes the product's aim: a crawler that marks and finds paths through the web and leaves it undisturbed.

The metaphor

Hikers build cairns above the tree line, where paths disappear. A cairn is visible from far away, anyone can read it, and it does not change the ground it sits on. Each property maps to a design rule in Cairn.

Words deliberately kept out of the name

These words were excluded from the product and executable name, meaning anything that appears as a process name, binary, package name or install path on the operator's machine. Many are accurate descriptions of what the software does. The aim is not to hide that, because the User-Agent says it plainly. The aim is to avoid tripping generic keyword heuristics that do not look at behaviour.

WordWhy avoided
botVery common in bot-management and WAF keyword rules, and in EDR detections for botnet clients. (The site-owner URL /bot keeps it deliberately; see below.)
crawler, spiderBot-management products and some proxy filters classify on these words before they look at behaviour
scraper, harvestSuggest content extraction. "Harvest" is also common in descriptions of credential-harvesting malware
stealth, ghost, shadowSuggest evasion, which is the opposite of Cairn's design. They are also frequent in malware and offensive-tool naming
sentinelCollides with EDR product names such as SentinelOne and Microsoft Sentinel, which confuses triage in the security console
beacon"Beacon" is Cobalt Strike's implant, so detections and threat-intel queries key on it. It was attractive as a metaphor and was rejected for that reason
Stealer-like or C2-like names (Lumma-, Vidar-, RedLine-, Raccoon-, Sliver-, Havoc-, Mythic-style)These are known infostealer and C2 family names. Anything close to them attracts both automated and human suspicion
The honesty rule outranks the keyword rule. On the wire, Cairn identifies itself fully and conventionally. The UA reads compatible; CairnSearch/1.0; +http://127.0.0.1:8787/bot (or CairnCorpus / Cairn-User). The info URL uses the conventional /bot path, as openai.com/bot does. Choosing a calm product name is about local process heuristics. It is never about making Cairn's traffic look like something else.

Collision check

A web search at the time of writing (2026-09-30) found no malware family, ransomware strain, C2 framework or offensive tool named Cairn. It did find one overlap to note:

Namespace overlap: Cisco Talos "CAIRN". In September 2026 Cisco Talos open-sourced a defensive research toolkit called CAIRN (Cognitive Artifact Intelligence Research Network), which tracks AI-integrated malware. It is not a malware family, so it should not trigger malware-name detections. However, a security analyst searching "Cairn" may find it first. Cairn's User-Agent tokens (CairnSearch, CairnCorpus, Cairn-User) and its /bot page make the distinction clear. If the overlap causes friction in a particular organisation, Wayfinder is the fallback name, since the tokens are defined in one place (src/identity.js).

If an EDR still flags Cairn

A calm name lowers the chance of a keyword-based false positive, but it cannot rule one out. Behavioural engines look at what processes do. Cairn starts a local HTTP server, spawns the Claude CLI, which in turn spawns a Node MCP server, and makes outbound HTTP requests to many hosts. Some EDR products score that pattern as suspicious.

The correct fix is an IT allowlist. It is never obfuscation. Ask your security team for an exclusion scoped by path, file hash or code-signing identity (publisher) for the Node.js and Claude CLI binaries, and optionally for the project directory. Do not rename binaries to look like system processes, pack or obfuscate scripts, run from temp directories to dodge path rules, disable or tamper with the EDR agent, or add any detection-evasion logic to Cairn. Each of these is a policy violation in its own right and would rightly turn a false positive into a real incident.
