Desktop assistant

Cairn Assistant is a personal assistant that runs on your Mac. It schedules reminders and recurring tasks, searches and researches, shops for you (research, compare, add to cart, but never pay), and does computer tasks such as file handling, terminal commands, Mac apps and browser automation. It is always on: every request runs in the background, so you can close the chat and hand off another task, and it asks for your approval before any risky action. The brain is the Claude CLI (claude -p) using your existing login. You reach it through a floating bubble that stays on top of your desktop.

1. What it does

Cairn started as a web retrieval and answer engine (see Architecture). The assistant layer adds a personal-assistant experience on top of it, modelled on ChatGPT Agent, ChatGPT Tasks and Grok. Everything runs on your Mac. The Cairn server listens only on 127.0.0.1:8787. Claude runs as a local CLI subprocess and is given a curated set of tools, and each tool call is either auto-approved (read-only or low-risk) or routed to you for approval.

⏰ Reminders & recurring tasks

"Remind me at 5pm", "every weekday at 8am brief me on the news". Cairn uses its own scheduler with macOS notifications. It can also write to Reminders.app and Calendar.app on request. Files: src/assistant/scheduler.js, when.js, macos.js.

🔎 Search & research

Live web search and page reading (Claude WebSearch / WebFetch), plus Cairn's own robots-respecting index and fetcher through the cairn MCP server. It runs multi-step research and cites its sources.

🛒 Shopping

It asks clarifying questions, researches, and gives you a comparison table (product, store, price, rating, link). It keeps a shopping list and can add items to a cart with your approval. It never enters payment details or places orders. Checkout is handed back to you. File: src/assistant/shopping.js.

💻 Computer tasks

It reads and searches files without asking. Shell commands, file writes and edits, and browser clicks or typing each need your approval. It can open apps and URLs and use the clipboard. It can drive a visible browser with the optional Playwright MCP server.

🌙 Always on, in the background

Every request is a background run that keeps going after you close the panel. Up to 3 runs execute at once and the rest wait in a queue. An Activity tab shows live progress, and macOS notifies you when a run finishes or needs you.

✋ Human in the loop

Risky tools go through Claude's --permission-prompt-tool to an Approve / Deny / Always allow card in the bubble, plus a notification. If nobody answers, the request is denied: after 5 minutes in chat, after 60 s for scheduled runs. File: src/assistant/approvals.js.

2. Always-on and background runs

Like ChatGPT Agent and Grok Bot, you hand off work instead of waiting on a chat reply. POST /api/assistant/chat returns 202 {runId, conversationId} right away, and the run's lifetime is independent of any browser connection. You can close the panel, quit the web view, or start three more tasks, and the run keeps going. The chat view is just a viewer that follows the selected run over SSE and replays buffered events when you reopen it.

A run moves between running and waiting_approval as many times as Claude asks for risky tools. A denial does not end the run. Claude is told why it was denied and adapts. Each state change is broadcast as run_update on /api/assistant/events.

This is what the leading assistants did as of September 2026, and what Cairn takes from each. The facts come from vendor announcements and help pages, with trade-press coverage where noted. See sources.

ChatGPT Tasks (OpenAI, beta from 14 January 2025)

"4o with scheduled tasks" lets ChatGPT run a prompt later, once or on a repeating schedule ("Remind me when my passport expires in six months", "Every Friday, give me a weekend plan"). Results arrive as push notifications or email and appear in the conversation. Tasks are managed on a Tasks page on the web. The beta limit was 10 active tasks, for Plus, Team and Pro. Cairn equivalent: TaskScheduler with two kinds of task. reminder sends a notification only. agent runs Claude unattended and notifies you with a summary. Tasks are managed in the bubble's Tasks tab.

ChatGPT shopping research and Instant Checkout (OpenAI)

  • Shopping research (24 November 2025, all logged-in users): it asks clarifying questions (budget, who it is for, must-have features), researches retailers and reviews, and returns a structured buyer's guide with prices, availability, trade-offs and "More like this / Not interested" refinement. It is powered by a GPT-5 mini variant trained for shopping. OpenAI warns it can get prices and availability wrong.
  • Instant Checkout (29 September 2025, US): "Buy it in ChatGPT", built on the open Agentic Commerce Protocol (ACP) co-developed with Stripe. Trade press reports that OpenAI wound it down in March 2026 after low merchant adoption and product-data accuracy problems. Checkout moved back to the merchant's own site or app.
Cairn's choice: research, compare and add to cart, then hand off checkout. Cairn never types card numbers, never stores payment data, and never places orders. The industry's move back to "discover in AI, buy on the merchant's site" supports this.

Grok: DeepSearch, Tasks and Grok Bot (xAI)

  • DeepSearch (with Grok 3, February 2025): an agentic search mode that synthesizes web and X results and reasons about conflicting sources.
  • Grok Tasks (mid-2025): scheduled prompts that run once, daily, weekly or monthly, including DeepSearch runs. Results arrive as notifications or email. Paid tiers get more tasks.
  • Grok Bot (announced 11 August 2026, early beta): a computer-use agent with its own cloud computer (a Linux VM with browser, file system and terminal). It works through multi-step jobs 24/7, even while your device is off, and comes back only when it needs human approval. Other reported features: "teach-a-task" (record a workflow once and it becomes a reusable routine), memory of earlier corrections, and desktop and mobile apps. This is the "always active, working in the background" behaviour Cairn's always-on model follows. Cairn runs locally, not in the cloud.

Claude in Chrome and Claude computer use (Anthropic)

  • Computer use (public beta, October 2024): an API tool that lets Claude see screenshots and control the mouse and keyboard. Anthropic recommends running it in an isolated VM or container with minimal privileges.
  • Claude in Chrome (research preview August 2025, then all Max users November 2025, then Pro, Team and Enterprise December 2025): a browser extension with site-level permissions and a "manually approve" mode. Even when a site is always allowed, it asks before publishing, purchasing, sharing personal data, downloading files or granting authorizations. High-risk site categories (financial services, adult content, piracy) are blocked, and classifiers watch for injected instructions. Anthropic reported that mitigations cut prompt-injection attack success from 23.6% to 11.2%, and on browser-specific challenge cases from 35.7% to 0%.
  • Claude Code CLI: headless claude -p with --output-format stream-json, MCP servers, --allowedTools, and --permission-prompt-tool. These are the parts Cairn builds on.

8. Safety model and approval policy

Cairn acts on your real computer, not a disposable VM, so the safety model is conservative by default. Four layers apply:

  1. Tool allowlist. Only read-only or low-risk tools are in --allowedTools. Anything else makes the Claude CLI call the permission tool.
  2. Human approval. mcp__assistant__approval_prompt puts the request in the ApprovalQueue. The bubble shows an Approve / Deny / Always allow card with a one-line summary and an input preview, and macOS shows a notification.
  3. Prompt rules. Never enter payment details or place orders. Ask before sending any message or email. In unattended runs, never ask questions.
  4. Platform guards. Loopback-only server. POST and DELETE require Content-Type: application/json, and any Origin must match (CSRF). Process spawns use argument arrays, never a shell. AppleScript strings are escaped. open_url accepts only http and https. There is a per-run budget cap, and every run is recorded in the audit log (kind:'agent', mode:'assistant').

Prompt injection. Web pages, emails and files can contain text written to steer an AI ("ignore your instructions and…"). Cairn's main defence is the approval gate. A page can make Claude want to run something, but it cannot approve it. Read the summary on each card before you approve, and keep autoApproveBrowser off unless you are working on sites you trust. Cairn has no injection classifier, unlike Claude in Chrome.
Payments. Cairn is instructed never to enter card or bank details or place orders. It stops at the cart and gives you the checkout link. If you ever see an approval card for typing into a payment form, deny it.

9. Reminders and recurring tasks

There are two kinds of task. A reminder is a notification at a time. An agent task is a prompt that Claude runs unattended at that time, and you are notified with the result. Both can repeat. Claude converts your wording into an exact local ISO time using the current date, time and timezone in its system prompt. The bubble's quick-add box uses parseWhen (src/assistant/when.js) for phrases like in 10 minutes, tomorrow at 9am, every weekday at 9 and every 30 minutes.

Figure 9 — Reminder lifecycle (state machine)
stateDiagram-v2
  [*] --> active: schedule_task or POST /api/assistant/tasks
  active --> firing: tick finds nextRunAt at or before now
  active --> firing: runNow (Run now button)
  firing --> active: recurring, nextRunAt advanced (missed runs skipped)
  firing --> done: one-shot task
  active --> cancelled: cancel_task, DELETE or Cancel button
  done --> [*]
  cancelled --> [*]
  note right of firing
    emit due exactly once
    reminder: macOS notification + SSE reminder
    agent: agent.runOnce(prompt) then markRun
  end note

firing is a short step inside a scheduler tick (every 5 s), not a stored status. Stored statuses are active, done and cancelled. If the Mac was asleep, an overdue one-shot fires once when Cairn next ticks. A recurring task skips to its next future occurrence instead of firing a burst of missed runs.

12. Conversation memory (--resume)

Each conversation stores the Claude CLI session id it last used. The next message in the same conversation spawns claude -p --resume <sessionId>, so Claude keeps the full context (earlier tool results, decisions, preferences you stated) without Cairn re-sending the history. If the CLI no longer has that session, the agent retries once without --resume.

Figure 13 — Conversation memory flow
sequenceDiagram
  participant B as Bubble
  participant A as AssistantAgent
  participant S as ConversationStore
  participant C as claude -p
  B->>A: startRun({conversationId, message})
  A->>S: get(conversationId)
  S-->>A: conversation (sessionId, allowAlways)
  alt sessionId present
    A->>C: spawn with --resume sessionId
    opt session missing on the CLI side
      C-->>A: error before any result
      A->>C: retry once without --resume
    end
  else first message
    A->>C: spawn without --resume
  end
  C-->>A: result (text, session_id, total_cost_usd)
  A->>S: append(assistant message with cost)
  A->>S: setSession(conversationId, session_id)
  A-->>B: result + done events

Memory is per conversation. A new chat starts clean, which also resets allowAlways. Files live in <dataDir>/conversations/<id>.json, and deleting a conversation in History removes the file.

17. Limits and honest differences

  • Local, not cloud. ChatGPT Agent and Grok Bot work on vendor VMs that keep running when your laptop is closed. Cairn runs on your Mac. While the Mac is asleep, nothing runs. Overdue one-shot reminders fire once on wake, and recurring tasks skip the runs they missed.
  • Server restarts interrupt runs. In-flight runs are marked error: interrupted in runs.json. The desktop watchdog restarts a crashed server it started, but it does not resume the interrupted runs.
  • Your real computer. Approved commands act on your real files. There is no sandbox VM. Keep workDir reasonable, and read approval summaries.
  • Browser sign-in. The Playwright browser uses its own profile, not your everyday browser. Sign in there yourself when a site needs it. Cairn does not store your passwords.
  • No cloud connectors, no teach-a-task, and no cross-conversation memory yet.
  • Costs. Each run uses your Claude plan or credits. The cost appears in the Activity tab and is capped by maxBudgetUsd.
  • Accuracy. Prices, stock and search results can be out of date or wrong, as vendors themselves warn. Cairn links every source so you can check.
  • Honest identity. Pages fetched through the cairn tools use Cairn's declared user agent and respect robots.txt. Browser automation is a real browser that you control and watch. Cairn does not evade bot detection or CAPTCHAs.
