Cairn for site owners

Cairn uses three clearly labelled user agents, one per purpose. Each follows your robots.txt and can be allowed or blocked on its own. This page explains what each one does, gives robots.txt rules you can copy, and shows how to check that traffic really comes from Cairn.

Every Cairn installation has its own operator. Cairn is self-hosted software. The +URL at the end of the User-Agent string and the From header on each request identify the installation and the person responsible for it. The /bot page at that URL shows the installation's exact user agents, IP ranges, signing key and contact address.

1. Cairn's user agents

CairnSearch

Crawls and indexes public pages so they can appear, with a link back to you, in answers and search results. Similar to OAI-SearchBot. Always follows robots.txt.

CairnCorpus

Collects pages into a dataset used for model evaluation or training. It only runs in explicit corpus jobs. Similar to GPTBot. Blocking it does not affect search. Always follows robots.txt.

Cairn-User

Fetches one specific page because a person asked a question, pasted a URL, or started a research task. It never crawls automatically. Similar to ChatGPT-User, but it follows robots.txt by default.

3. robots.txt recipes

Important: a group for a specific agent replaces your User-agent: * group for that agent. If you add a User-agent: CairnSearch group, even one that contains only Crawl-delay, CairnSearch stops reading your * rules. Copy any * rules you still want into the new group. This is standard RFC 9309 behaviour, and Googlebot and other major crawlers work the same way.

Recipe A: Opt out of datasets and training, stay in search

User-agent: CairnCorpus
Disallow: /

Recipe B: Block every Cairn agent

User-agent: CairnSearch
User-agent: CairnCorpus
User-agent: Cairn-User
User-agent: Cairn
Disallow: /

If you have no other Cairn-specific groups, User-agent: Cairn with Disallow: / is enough. Listing all tokens is the safest choice because it still works if you later add a role-specific group.

Recipe C: Keep some paths away from all Cairn agents

User-agent: Cairn
Disallow: /members/
Disallow: /checkout/
Disallow: /*sessionid=

Recipe D: Allow search for one section only

User-agent: CairnSearch
Allow: /docs/
Allow: /blog/
Disallow: /

The longest matching rule wins, so /docs/intro.html is allowed by Allow: /docs/, and everything else falls through to Disallow: /.

Recipe E: Allow search, block user-triggered fetches

User-agent: Cairn-User
Disallow: /

Recipe F: Slow down the search crawler

User-agent: CairnSearch
Crawl-delay: 10
Disallow: /private/        # repeat your * rules here, see the warning above

Recipe G: Help Cairn find your pages

Sitemap: https://www.example.com/sitemap.xml

Sitemap: lines apply to the whole file. Cairn follows sitemap indexes up to 3 levels deep. Sitemap URLs are still checked against robots.txt before they are fetched.

To test any of these, paste your robots.txt into the Robots tester in the Cairn web UI, or POST /api/robots/check with a robotsTxt field. It shows the decision and the matching rule for all three agents. robots.txt compliance has the full matching rules and 24 worked examples.

4. How long changes take

Change you makeWhen Cairn sees it
Edit robots.txtWithin 24 hours. Each installation caches robots.txt per origin for 24 hours. An operator can refresh it immediately by clearing the robots cache.
robots.txt returns an error (5xx, 429, timeout)Cairn keeps using your last good robots.txt. If it has never seen one, it treats the whole site as disallowed. It tries again after 10 minutes.
robots.txt returns 404 / 403 / 410Treated as "no restrictions" (RFC 9309), and cached for 24 hours
Add noindex or X-Robots-TagThe next time the page is fetched. The tags are read on every fetch.
Content already stored by an operatorrobots.txt and noindex control future fetching and indexing. They do not reach into copies an operator already saved. To ask for removal, contact the operator, who can run cairn index remove <url>.

5. Page-level controls (meta tags and X-Robots-Tag)

Use these when a page may be fetched but you want to limit what is stored or shown. They can apply to all agents, or be scoped to one Cairn agent.

<!-- all crawlers, including Cairn -->
<meta name="robots" content="noindex, nofollow">

<!-- only Cairn's search indexer -->
<meta name="CairnSearch" content="noindex">

<!-- every Cairn agent -->
<meta name="Cairn" content="nosnippet">
# HTTP response headers (also work for PDFs, JSON, images, …)
X-Robots-Tag: noindex
X-Robots-Tag: CairnSearch: noindex, nofollow
DirectiveEffect on Cairn
noindexNot added to the search index or a dataset, and never used as an answer source. A page a user asks for directly may be shown to that user once, but it is not stored.
nofollowLinks on the page are not crawled. rel="nofollow" on a single link does the same for that link.
nosnippetSearch results show no snippet, and answers can cite the page but never quote its text
noarchiveRecorded on the stored page, so views that would show a stored copy can hide it
noneThe same as noindex, nofollow

6. Verifying genuine Cairn traffic

Anyone can copy a User-Agent string. To be sure a request really came from a particular Cairn installation, check the stronger signals:

  1. User-Agent. It contains CairnSearch/1.0, CairnCorpus/1.0 or Cairn-User/1.0, and a +https://…/bot info URL. This is a claim only.
  2. Source IP. Fetch the IP list for that agent from the operator's info URL, and check that the connecting IP falls inside one of the listed prefixes: 
    $ curl -s https://<operator>/bot/cairnsearch.json
{"creationTime":"2026-09-30T08:00:00.000Z","prefixes":[{"ipv4Prefix":"203.0.113.0/28"},{"ipv6Prefix":"2001:db8:cafe::/48"}]}
  3. Cryptographic signature (strongest). Requests carry Web Bot Auth headers: Signature-Agent, Signature-Input (tag="web-bot-auth") and Signature (Ed25519). Fetch the public key from <Signature-Agent>/.well-known/http-message-signatures-directory and verify it. A CDN with a verified-bot program can also do this for you. Identity & Web Bot Auth has the exact algorithm and a reference verifier.

A local installation may publish only loopback ranges and a loopback key directory. Traffic that reaches the public internet should come from an installation whose operator has published real ranges and an HTTPS info URL.

7. Rate limits and politeness

429 Too Many Requests / 503The host is backed off exponentially (2 s, 4 s, 8 s … up to 60 s), and the request is retried at most 2 timesSend Retry-After (seconds or an HTTP date). It is honoured whenever it is longer than Cairn's own backoff.

Pacing is enforced centrally for each host, so running several crawl jobs at once does not multiply the load on your server.

8. What Cairn never does

  • Pretend to be a browser, rotate user agents, or rotate IP addresses to get around blocks
  • Try to evade bot detection, solve CAPTCHAs, or work around rate limits
  • Run JavaScript, submit forms, log in, or send anything other than GET
  • Follow a redirect into a path your robots.txt disallows
  • Use a page marked noindex as a stored answer source
  • Train on or collect content through CairnSearch or Cairn-User. Dataset collection only ever uses CairnCorpus.

9. FAQ

Does blocking CairnCorpus remove me from search?

No. The agents are independent. User-agent: CairnCorpus / Disallow: / only opts you out of datasets.

Does Cairn-User ignore robots.txt, like ChatGPT-User?

Not by default. OpenAI documents that robots.txt "may not apply" to ChatGPT-User because a user asked for the page. Cairn-User follows robots.txt unless the operator explicitly changes the respectForUserFetch setting. Even then, fetches are single pages requested by a person, clearly identified, rate-limited, and recorded in the operator's audit log as having skipped robots.txt. They are never used for automatic crawling or dataset collection.

Why do I see Cairn requests from 127.0.0.1?

That is a local installation, usually a developer testing Cairn against a site on their own machine. Its published IP range and key directory are loopback addresses too.

Do I need to do anything to be included?

No. If your robots.txt allows the agent, Cairn can fetch your pages. A Sitemap: line helps it find pages that are not linked from anywhere.

Will blocking Cairn affect other crawlers?

No. Cairn's tokens are only read by Cairn. Rules for Cairn, CairnSearch, CairnCorpus and Cairn-User do not affect Googlebot, GPTBot or anyone else.

10. Contact

Every request includes a From header with the operator's contact address. The same address appears on the installation's /bot page, which is linked from the User-Agent. Use it to report problems, ask for content to be removed, or ask for a slower crawl rate. Operators set this address with CAIRN_CONTACT or the contact setting. Please include the full User-Agent, the URLs, and the times of the requests, so the operator can find them in Cairn's audit log.
