Floating bubble app

Cairn.app is a small native macOS app (AppKit + WebKit, one Swift file) that puts Cairn Assistant on your desktop as a small animated avatar in an 88×88 window. There are three styles to choose from. The avatar floats above other windows on every Space and can be dragged anywhere. Click it, or Cairn's Dock icon, to open a chat panel. The app makes sure the Cairn server is running, and the avatar shows at a glance whether Cairn is idle, working, waiting for you or offline. If the server crashes, the app restarts it.

Quick start: node bin/cairn.js desktop --install builds the app, installs it as /Applications/Cairn.app, keeps it in the Dock and starts it. From then on, start Cairn whenever you need it from the Dock, Spotlight (⌘Space › Cairn), the Apps view (Launchpad) or the Applications folder. See Install & launch and Dock icon and menu bar.

2. Avatars and states

The bubble is an animated avatar. Each style is an ordinary web page in web/avatars/ that draws on a transparent canvas. The app shows it in a transparent WKWebView inside an 88×88 borderless window, so only the avatar itself is visible on your desktop. A transparent overlay view above the web view handles every click, drag, hover and right-click, so the avatar page never receives mouse events. build.sh copies the pages into Cairn.app/Contents/Resources/avatars, and the app loads them from there as local files. The avatar therefore keeps animating (in the offline state) while the server is down.

StyleFileLookRenderer
Aurora Orbweb/avatars/avatar-aurora.htmlA glass sphere filled with slowly flowing blue, cyan and violet clouds, with rim light and a soft glow. Comets orbit it while it works, one per running task, up to three.WebGL, with a 2D canvas fallback
Constellation Dotsweb/avatars/avatar-dots.htmlA tilted disc of glowing points around a soft core. It breathes when idle, swirls with trailing comets while it works, turns warm orange with a wave when it needs you, and fades to grey when offline.2D canvas
Buddyweb/avatars/avatar-buddy.htmlA glossy, friendly blob with eyes. It focuses with a spinning ring while it works, opens its eyes wide and glows orange when it needs you, and sleeps (with a "z") when offline.2D canvas
Classic Bubblenative, in CairnBubble.swiftThe original gradient circle with a stacked-stones glyph, progress ring and badge, drawn with Core AnimationAppKit. It is also the automatic fallback when an avatar page fails to load.

Choosing a style: right-click the bubble → Avatar and pick one. The current style has a checkmark, and the default is marked (default). The choice is saved in UserDefaults (CairnAvatarStyle) and applies straight away without a restart. The styles, their names and the default come from web/avatars/index.json ({default, styles:[{key, file, name}]}). The shipped file lists aurora (the default), dots and buddy. Without a valid index.json, every avatar-*.html in the folder is offered, named after its file, with the first one alphabetically as the default. Classic Bubble is always the last entry. To add a style, drop an avatar-<key>.html that implements window.cairnAvatar.setState into the folder, list it in index.json, and rebuild.

How health maps to the avatar's state

Every 3 seconds the app polls GET /api/assistant/health. It then calls window.cairnAvatar.setState(state, {running, approvals}) on the avatar page. The first matching rule wins:

#StateWhenWhat you see
1offlineThe health request failed (server starting, crashed or unreachable)The avatar dims and goes still, with a small grey dot (the Classic Bubble shows an amber dot)
2attentionpendingApprovals > 0, or an attention message (a reminder fired, or an approval arrived) in the last 10 sA pulse and a red badge with the number of approvals
3workingrunningRuns > 0. This count includes runs waiting for approval.Faster motion, orbiting activity, and a small counter when two or more runs are active
4listeningThe chat panel is openBrighter, with ripples, as if listening
5idleOtherwiseSlow, calm motion

The avatar page draws its own badge, counter and offline dot. The native ring, badge and dot are used only while no avatar page is loaded (Classic Bubble or fallback). If the avatar's web content process crashes, the app reloads the page.

4. Dock icon and menu bar

Cairn is a normal Dock app. While it runs, its Aurora Night icon sits in the Dock with a running dot, it appears in ⌘Tab, and the menu bar shows Cairn's menus whenever it is the frontmost app. The floating bubble works exactly as before: clicking it still does not take focus away from the app you are using.

ActionWhat happens
Click the Dock iconBrings the bubble back on screen (clamped to a visible display), opens the chat panel and puts the cursor in the message box, so you can start typing at once. If Cairn is already frontmost with the chat focused, the click hides the chat again, like a bubble click.
Click it while Cairn is hidden (⌘H)Shows the bubble (and the chat, if it was open) again, without toggling anything.
Start it again while it runsSpotlight, Launchpad, Finder, open -a Cairn and node bin/cairn.js desktop do the same as a Dock click. A second copy is never started.
Quit from the DockRight-click the Dock icon → Quit. The app stops a server it started, the same as every other way to quit.

Badge and bounce

  • Badge: the Dock icon shows a red badge with the number of approvals waiting for you (pendingApprovals from the 3-second health poll). The badge disappears at 0 and while the server is unreachable.
  • Bounce: when a new approval arrives, or a reminder fires, while Cairn is in the background, the Dock icon bounces once (requestUserAttention(.informationalRequest)). One event bounces it only once, even though the event stream, the chat panel and the health poll all report it. Further bounces wait at least 5 seconds.

Show in Dock

Right-click the bubble → Show in Dock (checked by default). Turning it off makes Cairn a bubble-only accessory app straight away: no Dock icon, no menu bar and no ⌘Tab entry, with the bubble's right-click menu as the whole UI. Turning it on brings them back. The choice is stored as CairnShowInDock and applied at every launch. From Terminal: defaults write com.cairn.bubble CairnShowInDock -bool NO (or YES), then restart Cairn. With it off, a Dock tile you pinned stays in the Dock as a launcher, and the icon may flash in the Dock for a moment at launch before Cairn switches itself to an accessory app.

Keeping it in the Dock

install.sh, and so node bin/cairn.js desktop --install, pins Cairn to the Dock once. After copying and registering the app, it checks defaults read com.apple.dock persistent-apps for a tile with the installed path (/Applications/Cairn.app, or ~/Applications/Cairn.app when that is where it installed). If there is none, it appends one with defaults write com.apple.dock persistent-apps -array-add … and runs killall Dock, so the Dock restarts once to show it. If the tile is already there, the Dock is not touched. Re-running the install never adds a second tile.

$ node bin/cairn.js desktop --install             # install, pin to the Dock (once) and start
$ node bin/cairn.js desktop --install --no-dock   # install or update, leave the Dock alone
$ bash desktop/install.sh --no-dock               # the same without the CLI (or CAIRN_NO_DOCK=1)
  • Unpin: right-click the Cairn icon in the Dock → Options → uncheck Keep in Dock. While Cairn is not running, the item is Options › Remove from Dock, or you can drag the icon out of the Dock. A later desktop --install pins it again unless you add --no-dock.
  • The automatic update done by plain node bin/cairn.js desktop (or bash desktop/run.sh) never changes the Dock.
  • Pin again: run node bin/cairn.js desktop --install, or drag Cairn from the Applications folder to the Dock. While it runs, you can also use Options › Keep in Dock.

7. Health polling and watchdog

The watchdog keeps an owned server alive. If this app started the server and three polls in a row fail (about 9 s), it terminates the child if it is still around and spawns a new one with the same command and baked environment. Runs that were in flight when the server died are recorded as error: interrupted in runs.json. The scheduler reloads tasks.json, so reminders are not lost. A server the app did not start is never restarted. Until it comes back you only see the avatar in its offline state.

Figure 4 — Health and watchdog state machine
stateDiagram-v2
  [*] --> launching
  launching --> healthy: server already running, or spawned and healthy
  launching --> unreachable: spawned server not healthy within 20 s
  healthy --> degraded: 1 failed poll
  degraded --> degraded: 2nd failed poll
  degraded --> healthy: poll succeeds
  degraded --> unreachable: 3rd consecutive failure
  unreachable --> restarting: app started the server (watchdog)
  unreachable --> unreachable: not our server, offline dot, keep polling
  unreachable --> healthy: poll succeeds
  restarting --> healthy: new child healthy
  restarting --> unreachable: still failing, retry on next failures
  healthy --> [*]: Quit Cairn
  note right of healthy
    every 3 s set the avatar state
    from runningRuns and pendingApprovals
  end note

The offline state appears from the first failed poll. The restart happens only when this app owns the server process, so a server you run in a terminal for debugging is left alone.

8. Click vs drag

The whole bubble is a drag handle and a button at the same time. The app tells the two apart by whether the pointer moved between mouse-down and mouse-up.

Figure 5 — Click-vs-drag interaction (state machine)
stateDiagram-v2
  [*] --> idle
  idle --> pressed: mouseDown (left button)
  pressed --> dragging: mouseDragged (pointer moved)
  pressed --> toggle: mouseUp with no movement
  dragging --> dragging: mouseDragged, window follows pointer
  dragging --> save: mouseUp
  save --> idle: clamp to visible screens, store in UserDefaults, re-place panel
  toggle --> idle: show or hide chat panel
  idle --> menu: right-click or control-click
  menu --> idle: item chosen or menu dismissed

A drag never opens the panel, and a click never moves the bubble. If the panel is open while you drag, it is placed again next to the bubble's new position.

9. Native ↔ web bridge

The panel content is the same web UI you can open in a browser (/web/bubble.html). Inside the app, it talks to the native shell through a WKScriptMessageHandler named cairn. In a normal browser, window.webkit does not exist, so these calls do nothing.

Figure 6 — Bridge messages and polling
sequenceDiagram
  participant W as bubble.js in WKWebView
  participant H as Swift handler cairn
  participant P as Chat panel
  participant BB as Bubble
  participant S as Cairn server
  W->>H: postMessage type collapse
  H->>P: hide panel (web state kept)
  S--)W: SSE reminder or approval on /api/assistant/events
  W->>H: postMessage type attention, title, message
  H->>BB: avatar attention state for 10 s
  opt auto-open setting on
    H->>P: show panel next to the bubble
  end
  loop every 3 s
    BB->>S: GET /api/assistant/health
    S-->>BB: runningRuns, pendingApprovals
    BB->>BB: window.cairnAvatar.setState(state, running, approvals)
  end

The JavaScript call is window.webkit?.messageHandlers?.cairn?.postMessage({type:'collapse'}) or {type:'attention', title, message}. Only the message types listed here have any effect.

11. Start at Login

Start at Login is opt-in only. The app never adds itself to your login items automatically. The toggle is in the bubble's right-click menu and in the Dock icon's menu. It uses osascript to ask System Events to add or remove a login item for the app's own path. The first time, macOS asks whether Cairn may control System Events.

The login item points to the copy you toggled it from, normally the installed /Applications/Cairn.app. If you switch between the build and the installed copy, or move the project, turn the toggle off and on again so the item points to the right path.

12. Install & launch

Install Cairn.app once and start it whenever you need it, like any other Mac app: from the Dock, Spotlight, the Apps view (Launchpad on macOS 15 and earlier) or the Applications folder. The icon is the Aurora Orb, the default avatar, on a midnight-blue tile. Its source is desktop/icon/icon.html. bash desktop/icon/render.sh regenerates desktop/icon/Cairn.icns from it, and build.sh copies that file into the app.

# from the project root: build if needed, quit a running Cairn, copy to /Applications, keep it in the Dock, start it
$ node bin/cairn.js desktop --install
$ bash desktop/install.sh                           # the same, without the CLI
$ node bin/cairn.js desktop --install --no-launch   # install or update without starting it
$ node bin/cairn.js desktop --install --no-dock     # install or update without adding it to the Dock
$ node bin/cairn.js desktop --install --rebuild     # force a fresh build first
install.sh stepDetail
BuildRuns build.sh if desktop/build/Cairn.app is missing or older than its sources (CairnBubble.swift, Info.plist, build.sh, desktop/icon/Cairn.icns, web/avatars/), or always with --rebuild.
QuitQuits any running Cairn, whether the build or an installed copy, with a normal Quit. If it is still running a few seconds later, it gets SIGTERM, which the app handles the same way. A server that Cairn started stops with it. A server you started yourself keeps running.
Copyditto to /Applications/Cairn.app, or to ~/Applications/Cairn.app if /Applications is not writable (CAIRN_INSTALL_DIR picks another folder). The copy keeps working away from the project because build.sh bakes absolute paths (project root, node, PATH, port) into its Info.plist. It still runs the server from this project and keeps your data in <project>/data, so do not move or delete the project folder.
SignChecks codesign --verify --deep --strict and re-signs ad-hoc (codesign --force --deep -s -) only if the copy no longer verifies
Registerlsregister -f on the installed copy, and lsregister -u on the build copy so that open -a Cairn and the Apps view resolve to the installed one (LaunchServices prefers /Applications anyway), then touches the bundle so Finder, the Dock and Spotlight pick up the icon. It never restarts Finder.
DockUnless you pass --no-dock (or set CAIRN_NO_DOCK=1): if com.apple.dock persistent-apps has no tile for the installed path, it adds one and restarts the Dock once (killall Dock). If the tile is already there, it changes nothing. See Keeping it in the Dock.
Launchopen /Applications/Cairn.app, then waits for /api/assistant/health to answer. --no-launch skips this step.

Starting it

  • Dock: click the Cairn icon. Once Cairn runs, the same click opens the chat.
  • Spotlight: press ⌘Space, type Cairn, press Return.
  • Apps / Launchpad: click the Cairn icon.
  • Finder: double-click Cairn in the Applications folder.
  • Terminal: node bin/cairn.js desktop (or bash desktop/run.sh) starts the installed copy if there is one, otherwise the build in desktop/build. open -a Cairn also works.
In the Dock while it runs. Cairn shows its icon in the Dock (with a running dot) and in ⌘Tab, and has a menu bar while it is frontmost. Click the Dock icon to open the chat. Right-click the Dock icon for Open Chat, New Chat, Open Dashboard, Open Docs, the task and approval count, and Start at Login. The floating bubble at the top-right of your screen keeps its own right-click menu, and ⌥Space still toggles the chat panel. Starting Cairn again while it is already running opens the chat; a second copy never starts. To go back to a bubble-only app without a Dock icon, right-click the bubble → uncheck Show in Dock.

Start at Login: to start Cairn every time you log in, right-click the bubble → Start at Login (see Start at Login). Turn it on from the installed app so the login item points to /Applications/Cairn.app. If you turned it on earlier from the build copy, turn it off and on again from the installed one.

Updating after code changes

After you change the Swift app, an avatar or the icon, upgrade Node or move the project, update the installed copy with the same command: node bin/cairn.js desktop --install. It rebuilds what changed, quits the old copy and starts the new one. Plain node bin/cairn.js desktop also updates an installed copy whose build is out of date before starting it. Changes to the server (src/, and web/ apart from the avatars) only need the server restarted, not a reinstall: right-click → Restart Server when Cairn started the server, or restart your own serve.

Uninstall: quit Cairn (Dock icon → Quit, or right-click the bubble → Quit Cairn), remove it from the Dock (right-click the icon → Options → Remove from Dock), then move /Applications/Cairn.app to the Trash. To remove its preferences and web data as well, see Uninstall.

13. Build and run

Requirements: macOS with the Xcode Command Line Tools (xcode-select --install provides swiftc and codesign), Node.js 20 or later, and the Claude CLI logged in (claude on your PATH or in ~/.local/bin). There are no npm dependencies.

# from the project root
$ node bin/cairn.js desktop --install # build, install into /Applications and start it (see Install & launch)
$ bash desktop/run.sh                 # start the installed app, or build if needed and open desktop/build/Cairn.app
$ node bin/cairn.js desktop           # the same, from the Cairn CLI (--rebuild, --restart, --quit also work)

# or step by step
$ bash desktop/build.sh               # → desktop/build/Cairn.app (ad-hoc signed)
$ open desktop/build/Cairn.app
$ pgrep -f Cairn.app                  # confirm it is running
$ osascript -e 'quit app "Cairn"'     # quit (also stops a server it started)
build.sh stepDetail
Bake pathsIt writes the project root, the absolute path from $(command -v node), and a PATH (node's directory, ~/.local/bin, /opt/homebrew/bin, /usr/local/bin, /usr/bin, /bin) into a generated Swift constants file or Info.plist keys. Apps launched from Finder do not inherit your shell PATH, so without this the app could not find node or claude.
Bundle avatarsCopies web/avatars/*.html (and index.json and any assets) into Cairn.app/Contents/Resources/avatars and checks that index.json, if present, lists existing files. The app loads the avatar from this bundled copy first, then from <project>/web/avatars. CAIRN_AVATAR_DIR overrides both. Rebuild after changing an avatar.
Compileswiftc -O -swift-version 5 -parse-as-library -framework Cocoa -framework WebKit → Cairn.app/Contents/MacOS/Cairn
Info.plistBundle id com.cairn.bubble, LSUIElement=false (a Dock app; the app switches itself to an accessory app when CairnShowInDock is off), NSAppTransportSecurity → NSAllowsLocalNetworking=true (allows plain HTTP to 127.0.0.1)
IconCopies desktop/icon/Cairn.icns to Contents/Resources/Cairn.icns (CFBundleIconFile Cairn). If that file is missing, it falls back to an icon drawn by the app's own bubble code (Cairn --render-icon).

The web UI also works without the native app. Run node bin/cairn.js serve and open http://127.0.0.1:8787/web/bubble.html in any browser. You lose only the floating avatar with its states, and the watchdog.

16. Uninstall

  1. If you turned on Start at Login, turn it off first from the right-click menu, or remove Cairn in System Settings → General → Login Items.
  2. Quit Cairn: right-click the Dock icon → Quit, right-click the bubble → Quit Cairn, or run osascript -e 'quit app "Cairn"'. This also stops a server the app started.
  3. Remove it from the Dock: right-click the Cairn icon → Options → Remove from Dock, or drag it out of the Dock.
  4. Move the installed app to the Trash: drag /Applications/Cairn.app (or ~/Applications/Cairn.app) to the Trash in Finder, or run osascript -e 'tell application "Finder" to delete POSIX file "/Applications/Cairn.app"'.
  5. Remove the build and the app's preferences and web data: 
    $ rm -rf desktop/build
$ defaults delete com.cairn.bubble
$ rm -rf ~/Library/WebKit/com.cairn.bubble ~/Library/Caches/com.cairn.bubble ~/Library/HTTPStorages/com.cairn.bubble
  6. Optional: revoke permissions in System Settings → Privacy & Security → Automation (and Reminders or Calendars), and in Notifications.
  7. Optional, and this deletes your history: remove assistant data from <dataDir>. That is conversations/, runs.json, tasks.json, shopping.json and assistant-settings.json. Reminders and events you created in Apple apps stay where they are.

Nothing is installed outside the project folder, /Applications/Cairn.app, the Dock tile and the standard per-app locations above. No launch daemons, kernel extensions, or background agents are installed.
